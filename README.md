# 객실 공지사항 오프라인 뷰어 (PDF · 폴더 분류 버전)

회사에서 내려받은 PDF를 **파일명 그대로** GitHub 저장소의 카테고리별 폴더에 올려두면, 앱이 폴더 구조를 자동으로 읽어서 분류하고 오프라인 저장까지 해주는 구조야. 파일명을 바꿀 필요가 전혀 없어.

## 1. 폴더 구조

`notices/` 폴더 안에 아래 7개의 카테고리 폴더가 미리 만들어져 있어. PDF를 해당하는 폴더에 그대로 넣으면 돼.

```
notices/
├── Safety&Security/
├── Service/
├── General/
├── Catering/
├── Schedule/
├── Manual/
└── Station Information/
```

- 파일명은 원래 이름 그대로 두면 돼 (예: `기내 면세품 신규 프로모션 안내.pdf`) — 이 이름이 그대로 화면에 제목으로 나와.
- 카테고리는 **폴더 이름**으로 정해져. 새 카테고리가 필요하면 `notices/` 아래에 폴더를 하나 더 만들면 자동으로 인식돼 (다만 화면 상단 필터 순서는 위 7개가 먼저 오고, 새 폴더는 그 뒤에 붙어).
- `notices/` 바로 아래에 폴더 없이 PDF를 올리면 "미분류"로 분류돼.

## 2. 올리는 법

1. 회사 시스템에서 공지사항을 PDF로 내려받는다. (파일명 변경 없이 그대로)
2. GitHub 저장소에서 해당 카테고리 폴더를 열고 **Add file → Upload files**로 PDF를 드래그해서 올리고 Commit한다. (휴대폰 브라우저에서도 가능해.)
3. 끝. 앱을 열거나 동기화 버튼을 누르면 자동으로 목록에 나타나.

별도 빌드나 배포 과정이 필요 없어. 앱은 저장소의 폴더 구조 전체를 한 번의 API 호출로 읽어와서(하위 폴더 몇 개든 상관없이) 분류해.

## 3. 처음 배포 (GitHub Pages)

OJT 평가 시스템 때와 같은 방식이야.

1. **공개(Public) 저장소**를 하나 만들고 이 폴더 전체를 올린다. (비공개 저장소는 GitHub API 인증이 필요해서 이 클라이언트 전용 구조에는 맞지 않아.)
2. 저장소 **Settings → Pages**에서 배포 브랜치/폴더를 지정한다.
3. 배포된 주소로 접속하면 **저장소 연결** 설정 창이 떠. 아래 정보를 입력하고 저장하면 바로 목록을 불러와.
   - GitHub 사용자/조직명 (예: `ruonlee`)
   - 저장소 이름
   - 브랜치 (보통 `main`)
   - 폴더 경로 (기본값 `notices`)
4. 팀 전체에게는 배포된 주소만 공유하면 돼. 각자 처음 한 번 이 설정을 입력하면 그 다음부터는 자동으로 동기화돼.
5. 스마트폰/태블릿에서 "홈 화면에 추가"를 하면 앱처럼 설치돼서 아이콘으로 바로 실행할 수 있어.

## 4. 오프라인 사용 흐름

- 인터넷이 될 때 앱을 열면 폴더 전체 목록이 자동으로 갱신돼.
- PDF는 기본적으로 한 번 열어본 것만 캐시돼. 비행 전에 전부 미리 받아두고 싶으면 **설정 → 전체 PDF 내려받기**를 눌러줘.
- 목록 카드에 "오프라인 저장됨" 표시가 있으면 인터넷 없이도 바로 열려. 표시가 없는 항목은 온라인일 때 한 번 열어야 저장돼.
- 오프라인 상태에서 아직 저장 안 된 PDF를 열면, 인터넷이 필요하다는 안내가 나와.

## 5. 참고

- 목록은 카테고리 순서(위 7개 기준) → 제목 가나다순으로 정렬돼. 날짜 정보는 따로 관리하지 않으니, 공지가 언제 올라온 건지 구분하고 싶으면 제목에 직접 표시해두는 걸 추천해 (예: "[9월] 기내 면세품 프로모션").
- 공개 저장소라서 회사 내부 보안 규정상 민감한 공지는 올리지 않는 게 안전해. 비공개로 운영해야 하면 그때 인증 방식을 추가하는 걸로 다시 설계하면 돼.
- GitHub API는 인증 없이 시간당 60회 요청 제한이 있어. 동기화는 앱을 열 때/온라인 전환 시/버튼 클릭 시에만 호출하니 일반적인 사용에서는 문제 없어.
